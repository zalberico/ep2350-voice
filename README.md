# EP-2350 Voice

A macOS feedback helper for the Teenage Engineering EP-2350 FX MIC. It detects the custom script's audio markers, shows a Listening toast and input meter, and provides shortcuts for opening Claude or Grok Bot. **Native voice conversations work without this helper.** The helper does not currently control native voice interruption or turn submission.

**Current release: 0.2.3, developer preview.** Your native voice app uses the service you are already signed into. This helper asks for no model or speech API keys and makes no model or speech API requests. The native service controls the conversation, spoken replies, interruption behavior, and subscription usage.

The intended everyday setup has **only the bottom audio cable connected to the microphone**. Run it on batteries; its separate USB data connection is for setup and diagnostics.

## What it does today

- **Shows local microphone feedback.** Squeezing displays a yellow microphone, **Listening**, and a live level meter near the top of the Mac screen. Releasing fades the toast out.
- **Opens native voice apps.** Choose Claude or Grok Bot from the menu bar helper, then start voice in that app. ChatGPT/Codex voice can use the same Sonos input directly; it does not need the helper's launcher.
- **Adds optional local LEDs on the mic.** A separately installed script shows two lower lights while held, three briefly on release, then restores the normal display. This runs entirely on the microphone and needs no ongoing USB data connection.

The microphone itself gates speech when its handle is held or released. Pressing the handle alone does not send a native interruption command; speaking while held can trigger the voice service's own speech-based interruption. The optional squeeze LEDs also run on the microphone, independently of the Mac app.

The helper detects markers generated by the custom microphone script. In native voice mode it does **not** transcribe your speech, copy text, send messages, or generate a replacement voice. The native app hears the microphone directly. **Listening** reports the local handle/input state; it does not mean the helper has submitted a turn or knows the assistant's state. That is why there is no **Sending** or **Sent** toast in this mode.

## What it does not do

- **Direct squeeze-to-interrupt or release-to-submit in native voice.** A native service may react to your speech, but the helper does not control its playback or turn submission. Shaking cannot retract audio it has already heard.
- **Show actual assistant thinking or speaking on the mic.** The current microphone-to-Sonos audio connection has no verified return channel for assistant status. A prototype requiring a second USB cable does not meet the intended everyday setup and is deferred.
- **Approve Codex permission prompts with the orange button.** This feature is blocked: there is no verified integration with the existing desktop chat's live approval prompt. The detector-only prototype was stopped; no new orange-button mapping is installed.
- **Run the Mac helper on an iPhone.** There is no iOS companion app in this repository. Sonos input and physical handle gating passed the Apple Notes dictation test on the iPhone Air; voice through Remote still needs testing. The microphone's own scripts remain on the mic, while Mac toasts, marker monitoring, and app controls do not automatically move to the phone.

The optional **Start voice (experimental)** menu action attempts to press a native app's voice-start button using Accessibility. The installed English button labels were inspected and matching/cancellation are tested, but this helper action has not passed a live call test. Starting voice manually in the native app is the verified workflow. AirPlay/HomePod output with the latest capture implementation is also unverified.

## Everyday use on Mac

1. Connect the mic's **3.5 mm output → Sonos USB-C Line-in Adapter → Mac**. Use batteries in the mic; leave its data USB cable disconnected.
2. Open your native voice app, select **Sonos** as its microphone input, and start a voice conversation. The tested output is the Mac mini's speakers.
3. Open **EP2350 Voice**. Right-click its menu bar handset and use **Native voice (subscriptions)** mode. Select Sonos for the helper's input and enable **Start handle feedback** if it is not already running.
4. Squeeze and speak to see the Listening toast and input meter; release to let the toast fade. If the optional LED script is installed, the mic's local lights respond as well.
5. End the voice call in its own app before starting another assistant. Changing the helper's provider selection does not end a call or transfer conversation history.

In 0.2.3, unplugging an actively monitored input puts native handle feedback into a waiting state. Reconnecting that same adapter resumes monitoring automatically within the original idle timeout. **Stop handle feedback**, changing input or mode, loss of microphone permission, or expiry of that timeout cancels automatic resume. Reopening is limited to three attempts; if it stops, choose **Start handle feedback** manually. Live unplug/replug verification is still pending. Version 0.2.2 stopped monitoring after unplugging and required a manual restart; that software limitation was separate from the microphone disk's eject warning.

The helper needs microphone permission for feedback. Accessibility is only needed for its optional experimental voice-start action and the older text-delivery workflow. You can start native voice manually without giving this helper Accessibility access. Native subscription limits and account usage settings still apply.

See [native voice behavior and limits](docs/native-voice.md) for details.

## iPhone as a wireless hub for the Mac

The intended mobile workflow is:

**EP-2350 → audio cable → Sonos adapter → iPhone → Remote voice → Mac mini**

The microphone supplies audio and runs its local scripts. The iPhone handles the voice connection. The Mac mini remains awake and online to run the chat's tools and project work. This basic workflow uses the existing ChatGPT subscription and Remote feature; it does not require this Mac helper to run on iOS or a new model API integration.

The first link has passed a user test in **Apple Notes dictation on iPhone Air**: whispered speech with the phone far away appeared while the handle was held, and did not appear when released. **The complete Remote voice path has not yet been tested with this mic/adapter.**

For that next test, open **Codex** in the ChatGPT iPhone app (or **Remote** if it still uses that label), select the connected Mac mini, open the desired chat, and start voice there. The phone and host must be paired to the same account/workspace, and the Mac must remain awake and online. A successful test should confirm both microphone input and a simple task executed on the Mac. See the official [Remote connection guide](https://learn.chatgpt.com/docs/remote-connections) and [voice documentation](https://learn.chatgpt.com/docs/features/voice).

For walking around with the phone in a pocket, also test that the same Remote voice call continues with the iPhone screen locked and that replies are audible. OpenAI documents **Settings → Voice → Background conversations** for mobile voice; the exact Remote/adapter combination still needs a live lock-screen test. See [background voice behavior](https://help.openai.com/en/articles/20001274-chatgpt-voice).

This path does not transfer the Mac's Listening toast to iOS or add the unimplemented approval button, direct playback control, or assistant-status LEDs. A separate iPhone companion would be new work and is not required merely to speak to the Mac-hosted chat through Remote.

An iPhone **Live Activity in Dynamic Island** is a possible future Listening display, using [Apple's ActivityKit](https://developer.apple.com/documentation/ActivityKit). The unresolved part is observing the handle markers while Remote uses the microphone: a second recording session may conflict with the voice call, and [audio-session activation can fail when another app hosts a call](https://developer.apple.com/documentation/avfaudio/avaudiosession/setactive(_:options:)). Concurrent input and background/locked-phone behavior must be tested before building that UI; a smooth live meter is not yet established.

## Build and install

Requires macOS 26 or newer, full Xcode for XCTest, and Python 3. Adjust the Xcode path if yours differs.

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
swift test -c release
python3 -B -m unittest discover -s Tests/Python -v
sh tools/build-app.sh
open 'build/EP2350 Voice.app'
```

For a per-user installation, quit any older running helper, copy `build/EP2350 Voice.app` to `~/Applications`, and open that copy. This preview is ad-hoc signed and is not notarized; macOS may ask for permissions again after an update.

## Microphone setup

**If firmware 1.1.2 and the compatible custom scripts are already installed, do not reinstall or flash them for a Mac app update.** The Mac app build does not write to the microphone.

A fresh device needs the custom marker script and samples before the helper can detect squeezes. Developer setup tools are `tools/build_fxmic_script.py` and `tools/install_mic.py`; the latter writes device scripts and samples, so it is a separate setup operation. Back up the device first, verify the normal **FX MIC DISK** volume, and read the tools before running them. Vendor firmware, generated vendor-derived scripts, factory files, and private backups are not distributed in this repository. Official hardware information is in the [Teenage Engineering guide](https://teenage.engineering/guides/ep-2350).

The [optional LED add-on](docs/led-overlay.md) is separate from the general microphone installer. It was installed and tested on the existing custom script without flashing firmware. Eject the mic's disk in Finder before disconnecting its data cable after setup. Keep backups private; a drive backup is not a firmware backup.

The current calibration was tested with Sonos in a quiet setup. Other adapters, volume settings, and speaking distances may require adjustment. Use the mic's line output with a suitable input, not directly with headphones.

```sh
swift run -c release fxmic-cal --list
swift run -c release fxmic-cal --device Sonos --meter --no-record --duration 20
```

## Older developer workflow

**Mode → Local transcription / bridge** retains the earlier local transcription and synthesized-reply experiment. Local English transcription, clipboard output, and squeezing to interrupt the prototype's own synthesized speech were tested. It requires an external connector to supply assistant replies and does not establish control of native ChatGPT, Claude, or Grok voice. It is separate from the default subscription-native workflow. See [the bridge protocol](docs/bridge.md).
